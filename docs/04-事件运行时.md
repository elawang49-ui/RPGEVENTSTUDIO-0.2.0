# 04 · 事件运行时

> 文档状态：早期架构设计草案，不是当前公共 API 清单。0.2.0-rc1 的实际方法、同步 handler/WAIT 协议、事务可见性和存档格式以 [发布接入说明](release/INSTALL.md) 及源码为准；本文尚未实施的检查点/调度预算等内容不能作为已交付能力。
> 对应需求文档 §19 第 5 项、§10 统一事件运行时。

---

## 1. 边界

`EventRunner` 只做四件事：

1. 按顺序解释执行 `EventCommand` 树（含条件、循环、调用）。
2. 管理异步等待与**取消**。
3. 管理多事件的并发、优先级、去重。
4. 把结果（完成/取消/失败）通知给调用方（事件、总控图、脚本）。

它**不做**：节点移动的具体实现（交给 `Presenter`/adapter）、状态存储（交给 `StateStore`）、UI 绘制（交给 `runtime/ui`）。

---

## 2. 状态机

```
                 ┌──────────────┐
                 │    IDLE      │
                 └──────┬───────┘
            start()      │
                 ┌──────▼───────┐
        ┌───────►│   RUNNING    │◄────────┐
        │        └──────┬───────┘         │ resume
        │   await 指令   │                 │
        │        ┌──────▼───────┐         │
        └────────┤   WAITING    ├─────────┘
                 └──────┬───────┘
        完成 / 取消 / 失败│
                 ┌──────▼───────────────┐
                 │ COMPLETED / CANCELLED │
                 │        / FAILED       │
                 └───────────────────────┘
```

- `WAITING` 分两类：`WAIT_ASYNC`（等信号、等 tween、等计时器）与 `WAIT_CONDITION`（等状态条件成立）。
- 终态不可回退；同一个 `EventInstance` 对象不复用，重跑就新建实例（避免脏状态）。
- 每个实例有 `instance_id`，日志与调试面板以此追踪。

---

## 3. 执行栈与帧

```
ExecutionFrame {
  event: EventRef           # 或 CommonEventRef
  page_index: int
  command_path: Array[int]  # 树内路径，如 [3, 0, 1] = 第3条的第一个子指令…
  index_in_list: int
  locals: Dictionary        # 事件局部变量（含 @@self 展开后的键）
  loop_stack: Array          # 每层: {type, counter, command_path}
  started_at: int            # msec，用于耗时统计
  scene_scope: int           # 绑定到的场景版本号
}
```

- 栈深 = 调用深度（事件 → 公共事件 → 公共事件），上限 `max_call_depth = 16`，超限 → `FAILED(recursion)`。
- `command_path` 是存档检查点的核心：恢复时按路径重新定位指令，不依赖指针。
- 循环用 `loop_stack` 记录剩余次数/条件，恢复时一并保存（这样循环中途存档也能续上）。

## 4. 指令执行契约

```
class CommandHandler:
    func execute(ctx: EventContext) -> int   # 返回值是控制流意图
```

| 返回 | 含义 |
| --- | --- |
| `CONTINUE` | 执行下一条 |
| `JUMP` | 跳转（条件分歧、循环用，目标写在 `ctx.jump_target`） |
| `HALT` | 打断本事件（`结束事件`） |
| `ABORT` | 中断并标记取消（`中断事件`） |
| `RETRY` | 条件等待型指令挂起（runner 会进 WAITING） |

规则：

- `execute()` 可以是协程（`await`），runner 直接 `await handler.execute(ctx)`。同步 handler 天然兼容。
- handler **不许**自己判断"是否已取消"，runner 在每次调用前后检查；长循环的 handler 必须在循环内查 `ctx.is_cancelled()`。
- handler 不许 `return` 前忘记 `ctx.advance_or_wait()` 之类副作用——所有副作用都走 `ctx`，便于 Mock 与日志。

## 5. 上下文（EventContext）

```
EventContext
  ├─ state: StateStore
  ├─ bus: EventBus
  ├─ presenter: Presenter        # 游戏=真 UI；编辑器=Mock（记录调用）
  ├─ adapters: {item, quest, enemy, player}
  ├─ args: Dictionary            # 公共事件参数 / 图节点传入参数
  ├─ locals: Dictionary
  ├─ runner_ref: WeakRef
  ├─ cancelled: bool
  ├─ func await_signal(obj, sig_name) -> Variant
  ├─ func wait(seconds: float) -> void
  ├─ func call_event(ref: EventRef) -> int      # 返回 完成/取消/失败
  ├─ func call_common(ref, args) -> int
  ├─ func is_cancelled() -> bool
  ├─ func log(msg)
  └─ func fail(reason) -> void
```

所有 `await` 必须经过 ctx，这样取消时能统一断开（见 §6）。**禁止** handler 里直接 `await node.some_signal`。

## 6. 等待与取消（本项目最容易出事故的地方）

三重保障：

1. **取消标志**：`ctx.cancel()` 置位 + 发 `cancelled` 信号；所有等待点用 `await ctx.await_any([signal, ctx.cancelled])` 语义实现，任一先到即返回。
2. **finally 恢复**：演出类指令（禁止玩家操作、锁定镜头、画面淡入）必须成对，且由 `ctx.on_cancel(callable)` 注册回滚。取消时按**逆序**执行回滚（栈结构）。
3. **场景绑定**：`ctx.scene_scope = 当前场景版本号`；场景切换时 runner 递增版本号，所有旧作用域实例强制取消。节点 `tree_exiting` 时也触发取消。

典型回滚登记：

```
禁止玩家操作 → on_cancel(恢复玩家操作)
淡入黑屏     → on_cancel(淡出回来)
镜头跟随切换 → on_cancel(恢复跟随)
显示对话框   → on_cancel(关闭对话框)
```

需求里"取消/断线后玩家卡在不能动"是这类插件最常见的 bug，验收用例必测：演出中途切场景、演出中途按 ESC 打断、演出中节点被 `queue_free()`。

## 7. 触发策略与去重

| 触发方式 | 数据来源 | 去重 |
| --- | --- | --- |
| 玩家按键交互 | `EventInteractor2D` 检测最近可交互对象 | 按键按下沿；同一实例运行中再按 → 按 `repeat_policy` 丢弃 |
| 玩家接触 | `Area2D` body_entered | 进入沿一次 |
| 进入/离开区域 | `Area2D` | 各自沿一次；快速来回用 `min_interval_ms` 节流（默认 120ms） |
| 自动执行 | 事件页条件满足即启动 | **三层防护**，见 §8 |
| 并行执行 | 同上，但不阻塞 | 同上 + 并行预算 |
| 其他事件调用 | `call_event` | 允许重入，但受 `max_call_depth` 限制 |
| 总控图调用 | `GraphRunner` | 图侧负责去重，runner 只执行 |
| 游戏信号 | `EventBus` 订阅 | 同帧合并 |

每个页面有运行时记录：`{last_started_tick, run_count, last_result, completed_generation}`。

---

## 8. 自动事件死循环的三层防护

自动事件（autorun）最常见的事故：条件一直满足 → 执行完立刻重触发 → 每帧执行 → 卡死。

1. **完成标记**：页执行成功后写 `completed_generation = 当前状态修订号`。条件未变化（修订号相同）时不再触发。
2. **状态修订号**：`StateStore` 每次批量提交递增 `revision`。autorun 页只在 `revision > 上次执行时的修订号` 时重新评估。
3. **每帧预算**：autorun 事件每帧最多执行 `autorun_budget_ms`（默认 1.5ms）或 64 条指令，超出挂起到下一帧；连续 120 帧都在执行 → 强制中止并报"疑似自动事件死循环"（调试面板红条）。

再加一道开发期检查：`GraphLinter`/`EventPageAnalyzer` 对"无条件 + 自动执行 + 内部只是等待"的页直接告警。

---

## 9. 并行事件与性能

- 并行事件在 `RUNNING` 态下按"指令预算"切片：每帧每实例最多 `parallel_budget_ops = 32` 条同步指令。
- 所有实例按 `priority` 升序调度；同优先级 FIFO。
- 总预算 `frame_budget_ms`（默认 4ms）用尽后，剩余实例推到下一帧（不丢，只延迟）。
- 调试面板显示：活跃实例数、每实例耗时、本帧预算占用。需求 §3.3 的"并行事件性能问题"在这里闭环。

## 10. 公共事件调用

```
call_common(common_ref, args) -> 结果
```

- 参数按 `ParamSpec` 校验（类型/必填），缺失用默认值；校验失败 → `FAILED(invalid_args)`，不进入执行。
- 递归检测：调用链上同一 `common_id` 出现次数 ≥ `max_recursion`（默认 8）→ 中止并报错，日志打印完整调用链。
- 公共事件默认**串行等待**（调用方挂起）；`is_parallel: true` 的公共事件可 fire-and-forget，但需显式声明。
- 公共事件内 `@@self` 非法（见 `docs/03` §2），校验器拦截。

## 11. 结果三态与通知

```
enum Result { COMPLETED, CANCELLED, FAILED }
CompletionReport {
  result: Result
  instance_id: int
  event_ref: EventRef
  reason: String        # 失败原因 / 取消来源（调用方 / 场景切换 / 用户打断）
  duration_ms: int
  steps_executed: int
}
```

- 事件结束时：`bus.event_finished.emit(report)` + 若有调用方则 `await` 返回该结果。
- 总控图的 `Event` 节点按配置处理：`失败视为完成`（默认关闭）/ `失败则中断图` / `失败则走错误分支`。
- 失败**不吞异常**：`FAILED` 一定带 reason，并在编辑器里高亮到具体指令（`command_path`）。

---

## 12. 场景切换清理

`SceneTree` 切场景后，旧场景节点全部失效。清理顺序：

1. 递增 `scene_scope` → 所有旧实例收到取消。
2. 强制 `queue_free` 旧 UI（对话框、演出遮罩）。
3. 清理 `EventInteractor2D` 注册表（按 `is_instance_valid` 过滤 + 每场景重建）。
4. 保存"跨场景存续"的状态（`StateStore` 天然跨场景，无需处理）。
5. 新场景 `_ready` 后重建注册表、重新评估自动事件、恢复图（若图是跨场景的）。

## 13. 检查点

```
Checkpoint {
  version: int
  instance_id: int
  stack: Array[ExecutionFrame]   # 只存最内层必要字段
  vars: Dictionary               # 事件局部变量
  saved_at: int
}
```

- 写入时机：每条指令执行**前**更新"上一边界"，执行后提交。存档取最后提交的边界。
- 恢复：重建栈 → 从边界指令**重新执行**（幂等指令安全；非幂等指令如"给予道具"标记 `non_idempotent`，恢复时跳到下一条并记警告）。
- 需求 §13 允许"安全检查点"而非任意指令精确恢复，这个模型正好卡在边界上。

## 15. 条件树（事件页与条件分歧共用）

```
ConditionNode
 ├─ kind: ALL / ANY / NOT / LEAF
 ├─ children: Array[ConditionNode]
 └─ leaf: { key, op, value }  # 或 { kind: SCRIPT, callable_name }（受限）
```

- 编译器把 ALL/ANY/NOT 折成扁平求值，短路求值。
- 支持 `has_item`、`quest_state`、`stage` 等**语义叶子**，底层用 adapter 查询，不是字符串脚本。
- 自定义条件：只允许"引用已注册的 `ConditionProvider`"（脚本实现接口后注册），**不允许**在数据里写表达式字符串。这是防止 AI 注入与误执行的关键边界（需求 §15）。

## 16. 一次演出的时序（示例）

```
玩家按键
  → EventInteractor2D 找到 event "basement_intro"
  → runner.start(ref)
      → 页选择（最大满足条件页）
      → CmdLockPlayer      (on_cancel: unlock)
      → CmdCameraMove      await tween(1.0s)
      → CmdPlaySfx
      → CmdShowActor       (on_cancel: hide)
      → CmdMoveActor       await tween(1.6s)
      → CmdWaitMoveDone    （handler 内部 await，不额外等待）
      → CmdPlayAnim
      → CmdShowText        await presenter.show(...)
      → CmdCameraBack      await tween(0.8s)
      → CmdUnlockPlayer    (撤销 on_cancel)
      → CmdSetState        School.VisitorDone = true
      → 结束 → bus.event_finished(COMPLETED)
  → GraphRunner 收到 → 激活追逐阶段节点
```

任何一步被取消：逆序回滚 → 解锁玩家、关闭对话框、恢复镜头 → `event_finished(CANCELLED, reason)`。
