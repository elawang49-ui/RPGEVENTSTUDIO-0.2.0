> 这轮不开发新玩法，只做两件事：**让人能学会用**、**把「必须懂内部实现」的地方改掉**。
> 检查方式：按 `docs/14-上手教程` 的步骤，用编辑器真实按钮走完整流程；
> 步骤背后的操作同时写成 `tests/tutorial_flow.gd`（14 项）自动验证，防止教程与实现脱节。

## 1. 走一遍流程后，最妨碍创作的 6 件事

| # | 原来的体验 | 创作者的真实感受 | 本轮处理 |
| --- | --- | --- | --- |
| 1 | 条件、开关、变量都要求手输 `School.Office.DiaryFound` | 「我记不住，也怕打错一个字母」 | ✅ 新增**状态库 + 显示名称**；条件/开关/变量/图节点全部改成**下拉选择** |
| 2 | 条件值要填 `true` / `false` | 「为什么不是「是/否」？」 | ✅ 开关类状态自动变成**是 / 否**下拉，比较符锁定 `==` |
| 3 | 新建事件要去文件系统右键 → 搜脚本 → 另存 | 「我不知道该存哪、也不知道要挂到节点上」 | ✅ 事件面板加 **「新建事件…」**，保存后**自动挂到选中的节点** |
| 4 | 关卡图只能「打开…」，不能新建 | 「第一张图从哪来？」 | ✅ 关卡图加 **「新建…」**，新图自带「开始」节点 |
| 5 | 图里节点没填参数也能存，运行时静默不动 | 「为什么没反应？」 | ✅ 画布下方常驻**参数检查**：绿字=没问题，橙字列出缺参数的节点 |
| 6 | 事件没触发，完全没有提示 | 「到底哪一页、哪一条条件不对？」 | ✅ 运行期 **F2 状态面板**：显示每个状态的当前值 + **「最近没有执行的事件」逐页逐条件说明** |
| 7 | 关卡图「调用事件」固定按「交互」找事件页 | 「我的事件页写的是自动执行，为什么图里调不动？」 | ✅ 事件节点新增 **「触发方式」** 参数（默认交互），字段下方有说明；诊断里也会提示触发方式不匹配 |

## 2. 状态：内部标识与显示名分离（本轮主要改动）

### 2.1 最小方案（没有重建状态系统）

```
StateDefinition（一条定义）
├─ key           内部标识，如 School.Office.DiaryFound   ← 事件/图里只存这个
├─ display_name  显示名称，如「办公室日记已调查」          ← 所有界面显示这个
├─ type / default / category / description
└─ 存在 res://state/state_catalog.tres（StateCatalog）
```

- 读取入口统一为 `StateCatalogStore`：编辑器（事件面板、关卡图、状态库）和运行时（F2 面板、指令摘要、图节点摘要）共用同一份。
- 事件与图的数据**没有增加任何字段**：仍然是 `key`。所以旧 `.tres` 一行都不用改。
- 显示名改了只影响展示；测试用例专门验证「改名后内部标识不变、事件照常工作」。

### 2.2 旧资源怎么兼容

- 旧事件里的 `School.Office.DiaryFound` 如果没登记：选择器显示 `⚠ School.Office.DiaryFound（未登记，点 + 登记）`；
- 点 `+` 会以这个 key 建一条定义，显示名默认等于 key，然后你可以在状态库里改成中文；
- 没有全局迁移、没有重命名，**旧数据不可能被改坏**。

### 2.3 高级用户

- 事件面板勾 **「显示标识」**：所有下拉后面追加 `（内部标识）`，方便排查。
- 状态库里**内部标识只读**，显示名称可随便改。

## 3. 教程本身

`docs/14-上手教程-从零做一段剧情.md`，按「选中什么 → 点哪个按钮 → 填什么 → 看到什么」写，覆盖：

1. 登记状态（状态库）
2. 新建调查事件（新建事件… → 条件 → 指令 → 存盘）
3. 把事件挂到 NPC/门/抽屉（三种组件怎么选）
4. 第二个调查点
5. 关卡图：什么时候该用图、什么时候用局部事件；加节点、连线、参数
6. 图调用一段剧情事件（并解释「等待事件结束」）
7. 运行与检查（F5 / F2）
8. 出错排查（5 类常见原因，含「触发方式不匹配」）
9. 以后怎么加调查点 / NPC 对话 / 剧情分支
10. 速查表 + 演示工程对应文件

文档里的每一步都有对应的自动验证：`tests/tutorial_flow.gd` 用**按钮背后的同一套方法**从空白资源建状态、建事件、建图、连线、保存、运行，断言「两条线索 → 自动解锁」。
