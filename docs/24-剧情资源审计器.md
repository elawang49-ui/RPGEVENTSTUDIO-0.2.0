# 24 · 全工程剧情资源审计器

> 基线：`be04593`（integration/tasks-2026-10-30）。
> 分支：`feat/story-resource-audit`。对应盘点清单第 8 项。

## 1. 目标与边界

**做**：一键扫描全工程的剧情资源，把「会静默失效」的问题汇总成可筛选、可定位的报告：

- 空事件 / 所有页面无指令
- 事件 `event_id` 重复、关卡图 `graph_id` 重复
- 场景 / 关卡图里写下的 `event_path`、`graph_path` 失效，或指向错误资源类型
- 事件里「调用公共事件」的目标不存在
- 音频路径不存在
- 事件里使用但状态库未登记的状态
- 关卡图静态校验（直接复用 `GraphValidator`，含开始节点、端口、参数、事件路径、循环等）
- 从未被任何场景 / 关卡图 / 公共事件引用的事件或关卡图（提示级）

**不做**：

- 不修改任何资源，不自动修复；审计只读。
- 不实例化场景（`EventReferences` 解析文本），因此不会展开场景实例内部，也不会执行 `@tool` 脚本。
- 不检查脚本里动态 `load()` 的引用；这类资源会显示为“未引用”（与现有事件列表口径一致）。
- 不改变任何 `.tres` / `.tscn` 序列化格式。

## 2. 实现结构

| 文件 | 职责 |
| --- | --- |
| `core/audit/story_audit.gd` | 纯逻辑扫描：收集事件/图、`EventReferences` 引用、`GraphValidator` 结果、状态库比对，产出统一 issue 列表 |
| `editor/audit/story_audit_panel.gd` | 主屏「审计」页：扫描按钮、严重级别筛选、Tree 列表、详情、双击定位信号 |
| `plugin.gd` | 注册第 4 个主屏标签、连接定位、`RPGEVENTSTUDIO_AUDIT_SELFTEST` 钩子 |
| `core/audit/event_references.gd` | 新增可选 `root` / `excludes` 参数；默认行为不变 |
| `tools/check_i18n.gd` | 识别 `audit.*` 文案前缀；排除审计问题码（机器标识） |
| `tests/story_audit_test.gd` | 24 项 headless 用例 |
| `tests/story_audit_editor_selftest.gd` | 14 项真实编辑器用例 |
| `tests/fixtures/audit/` | 6 个事件、2 张图、1 个场景的固定夹具 |

问题 Dictionary 字段：`code / severity / category / path / node / node_name / message_key / params / hint_key / message / hint`。
`message_key` 为空时 `message` 已是本地化文本（来自 `GraphValidator`）。

## 3. 问题码

| code | 级别 | 来源 |
| --- | --- | --- |
| `event.empty` | 错误 | 事件没有任何页面 |
| `event.no_commands` | 警告 | 所有页面都没有指令 |
| `event.duplicate_id` | 错误 | 多个事件共用 `event_id` |
| `event.unreferenced` | 提示 | 无场景/图/公共事件引用 |
| `event.no_name` | 提示 | `display_name` 为空 |
| `state.unregistered` | 警告 | 指令里的状态未登记 |
| `common.missing` | 错误 | `call_common` 目标不存在 |
| `sfx.missing` | 警告 | `play_sfx` 音频不存在 |
| `ref.broken` | 错误 | 场景/图的引用目标不存在 |
| `ref.not_event` | 警告 | 引用目标不是事件/关卡图 |
| `graph.duplicate_id` | 错误 | 多张图共用 `graph_id` |
| `graph.unreferenced` | 提示 | 无场景挂载该图 |
| `graph.<GraphIssue.code>` | 沿用 | 关卡图静态校验错误/警告（INFO 默认折叠） |

## 4. 使用

1. 启用插件，打开主屏「Event Studio」。
2. 切到第 4 个标签「审计」。
3. 点「扫描工程」。默认排除 `res://.godot`、`res://tests`、`res://tools`。
4. 用右上角筛选只看错误/警告/提示；选中一行看详情；双击：
   - 事件 → 打开事件编辑器（同时同步剧情工作台）
   - 关卡图 → 打开主屏关卡图
   - 场景 → 在编辑器中打开场景

审计读取磁盘文件；先保存再扫描，未保存的修改不会计入。

## 6. 已知限制

- 只解析 `.tscn` / `.tres` 文本，不展开场景实例；子场景会单独扫描，不会漏引用。
- 脚本动态 `load()` 无法静态确认；会被当作未引用。
- `@@self` / `@@level` 局部状态键不做未登记判断（运行时才确定前缀）。
- 关卡图 INFO 默认不显示，避免噪音；可通过 `StoryAudit.scan({"graph_info": true})` 打开。
- 未做导出/CI 集成；报告暂不支持导出 CSV/JSON（后续可与压力测试共用报告层）。
