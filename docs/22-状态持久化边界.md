# 状态持久化边界

RPGEVENTSTUDIO 的 `StateStore` 与游戏自己的 `GameState` 是两套系统，不要做键级强行合并。

## 分工

| 系统 | 负责 |
| --- | --- |
| `GameState` | 分数、觉察、线索、章节、flags、最终选择、游玩时长 |
| `StateStore` | 事件开关/变量、`@@self.*` 局部状态、条件判断、事件运行 revision |
| 存档桥 | 把 `StateStore.snapshot()` 作为不透明 `event_state` 字段写入游戏存档 |

《做题家》的桥在 `scripts/integration/studio_state_bridge.gd`：

- `capture()` → `{format, revision, values}`
- `restore(data)` → 有 `values` 时恢复；旧存档没有 `event_state` 时清空会话内插件状态，避免串档
- `reset()` → 新游戏/回标题时清空

## 存档格式

`user://case_001_save.json` 增加可选字段：

```json
"event_state": {
  "format": 1,
  "revision": 42,
  "values": {"School.Office.PcChecked": true}
}
```

`GameState.chapter_snapshot` 也带同一份快照；章节重开时恢复到章节入口，
继续游戏时恢复到存档时的当前状态。

## 不做什么

- 不把 `flags` 自动镜像成 `StateStore` 键，也不反向镜像。
- 不把事件局部状态写进剧情 flags。
- 不要求插件核心知道《做题家》的存档路径；桥属于游戏工程。
- 旧存档没有 `event_state` 时不会崩溃，但会清空事件状态（不会尝试猜测）。

## 验收

- `tools/test_narrative_adapter.gd` 覆盖：写入存档、读档恢复、章节重开、新游戏清空、
  旧存档缺字段时清空插件状态且保留 GameState flags。
- 其他游戏接入时需要实现同等的 `capture/restore` 桥；插件不绑定任何游戏存档格式。
