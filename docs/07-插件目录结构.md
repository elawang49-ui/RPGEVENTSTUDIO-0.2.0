## 1. 实际目录（已建）

## 2. 目录职责与硬性规则

| 目录 | 允许依赖 | 禁止 | 备注 |
| --- | --- | --- | --- |
| `core/model` | `core/util` | 任何 `Node`、`SceneTree`、`EditorInterface` | 纯数据，可在 `@tool` 与运行时共用 |
| `core/state` | `core/model` | UI、`Node` | 实例化两份（编辑器/运行时） |
| `core/runtime` | `core/model`、`core/state`、`core/adapters` | `editor/*`、`GraphEdit`、`EditorUndoRedoManager` | 用 `Presenter` 抽象隔离 UI |
| `core/graph` | 同 runtime | 同上 + `GraphEdit` | `GraphRunner` 只认数据 |
| `core/adapters` | 无 | 具体游戏类 | 全部 `Object`/`Callable` 接口，默认空实现 |
| `editor/*` | `core/*`、Godot 编辑器 API | 被 `core` 反向引用 | 只在编辑器进程加载 |
| `runtime/*` | `core/*` | `editor/*`、`EditorInterface` | 游戏内 |
| `samples/*` | 全部 | — | 仅示例，发布时可剔除 |

**三条机械规则**（用 `tools/check_deps.gd` 在 CI/提交前扫）：

0. 游戏代码里出现裸按键（`KEY_*` / `JOY_*` / `MOUSE_BUTTON_*`，`samples/` 与测试除外）→ 失败：输入必须走 `InputService` 动作名。
1. `core/` 里出现 `"res://addons/rpgeventstudio/editor/` 或 `EditorInterface` 字样 → 失败。
2. `core/` 里出现 `extends Node` / `extends Control` → 失败（数据与服务必须是 `Resource`/`RefCounted`）。
3. 单个 `.gd` 文件 > 400 行 → 警告；> 600 行 → 失败。
4. 用户可见文案必须经由 `L10n.ui()` / `L10n.game()`；`core/` 与 `runtime/` 里出现中文字面量 → 警告（示例与翻译源文件除外）。

## 3. 命名规范

| 对象 | 规范 | 例 |
| --- | --- | --- |
| 目录 | `snake_case` | `level_graph/` |
| 脚本 | `snake_case.gd`，类名 `PascalCase` | `event_runner.gd` → `class_name EventRunner` |
| 指令 handler | `cmd_<指令id>.gd`，类名 `Cmd<Pascal>` | `cmd_show_text.gd` → `CmdShowText` |
| 资源文件 | `<event_id>.tres` / `graph_<graph_id>.tres` | `librarian.tres`、`graph_school.tres` |
| 场景 | `*_panel.tscn`（编辑器）、`*_view.tscn`（图） | `event_editor_panel.tscn` |
| Autoload 名 | `RPGEventStudio` | 只此一个 |
| 命令/信号 | 事件用过去式，方法用动词 | `event_finished`、`set_state` |

**Autoload 只注入 1 个**：`RPGEventStudio`（指向 `runtime/autoload/studio_runtime.gd`）。其余服务都是它的成员，避免 `project.godot` 里出现一长串插件 autoload（侵入性与卸载残留的主要来源）。

## 4. 对宿主项目的侵入清单

启用插件后，对宿主 `project.godot` 的改动**仅限**：

| 键 | 值 | 禁用时是否移除 |
| --- | --- | --- |
| `autoload/RPGEventStudio` | `*res://addons/rpgeventstudio/runtime/autoload/studio_runtime.gd` | ✅ 自动移除 |
| `input/rpg_event_studio_interact`（可选） | 默认 `Space`/`Enter` | ✅ 仅在插件创建时移除（不覆盖用户自定义） |
| `rpg_event_studio/*`（插件自有命名空间） | 配置项 | 保留（下次启用复用） |

不做的事：不改 `main_scene`、不改场景根节点、不换 `InputMap` 的既有动作、不 override `_input`（交互由组件自己处理）。

**卸载步骤**（文档化给用户）：禁用插件 → 删除 `addons/rpgeventstudio/` → 删除 `res://events/`、`res://levels/`、`res://state/`（数据目录，插件不会自动删）。

## 5. 打开/关闭的生命周期

```
_enter_tree()
  ├─ register_autoload()          → autoload/RPGEventStudio
  ├─ register_input_action()      → 仅在缺失时创建
  ├─ register_docks()             → 事件编辑器 / 状态监视 / 执行日志
  ├─ register_inspector()         → EventDefinition / StateCatalog
  ├─ register_main_screen()       → 关卡总控图
  ├─ register_scene_types()       → EventInteractor2D 等自定义类型（4.7: add_custom_type）
  └─ connect_editor_signals()     → selection_changed / resource_saved / scene_changed

_exit_tree()
  ├─ 按逆序全部注销（含 remove_autoload_singleton）
  ├─ 关闭所有 DocumentManager 打开的文档（含未保存询问）
  └─ 断开所有 signal
```

`_exit_tree` 中任何一步抛错都不许中断后续清理（每步 `try` 语义用 `if is_instance_valid(...)` + 单独函数包裹）。**残留 autoload 是插件最典型的用户投诉**，这一条会写进测试。

## 6. 发布打包

`tools/package.sh`：
1. 复制 `addons/rpgeventstudio/` 到临时目录。
2. 剔除 `samples/`、`editor/themes/*.png` 中未引用的资源（可选）。
3. 校验所有 `.gd` 可解析（headless `--check-only`）。
4. 打 zip，命名 `rpgeventstudio-<version>.zip`，根目录为 `addons/rpgeventstudio/`（符合 Godot 资源库格式）。

## 7. 数据目录（宿主项目内，由用户创建）

```
res://
├── events/<level_id>/<event_id>.tres
├── common_events/<common_id>.tres
├── levels/<level_id>/graph_<graph_id>.tres
└── state/state_catalog.tres
```

插件首次启用时可提示"创建数据目录"，但**不强制**（用户可放到任何位置，通过项目设置指定根目录）。
