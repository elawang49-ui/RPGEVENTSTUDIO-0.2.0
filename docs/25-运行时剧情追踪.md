# 25 · Runtime Trace 运行时剧情追踪

> 基线：`integration/stage2-2026-10-30` @ `096ac8f`。
> 分支：`feat/runtime-trace`。

## 1. 目标

让开发者回答：事件为什么触发、为什么选中这一页、正在执行哪条指令、条件实际值、
状态改了什么、为什么进入某个图分支、事件如何结束/取消/失败。

追踪只观察，不驱动执行；不改变存档结构；关闭后零记录。

## 2. 数据模型

统一服务 `core/trace/runtime_trace.gd`（`RuntimeTrace`，RefCounted），
所有记录带 `seq` / `t_ms` / `kind` / `trace_id`。

| kind | 关键字段 | 含义 |
| --- | --- | --- |
| `event_start` | event_id / event_name / event_path / trigger_filter / page_index / source / parent_trace_id / depth | 事件开始；source 可为 graph / interactor / trigger_area / autorun / nested |
| `page` | page_index / trigger / trigger_ok / active / selected / conditions | 每一页的选择结果与逐条件实际值 |
| `event_end` | result(completed/cancelled/failed) / reason / duration_ms | 事件结束 |
| `event_rejected` | event_id / pages / source | 没有任何页命中，记录真实触发来源 |
| `event_ignored` | event_id / reason(reentry·repeat_policy) / detail / source | 被忽略：同一事件正在执行 / 执行策略不允许 |
| `command_start` | command_serial / command_index / command_type / depth | 指令开始 |
| `command_end` | result(continue/wait/enter_block/call/halt/abort) / duration_ms | 指令结束 |
| `condition` | key / op / expected / actual / matched / branch；图条件额外带 graph_id/node_id（trace_id=0） | 条件判断与进入的分支 |
| `state` | key / old / new / existed / trace_id / command_index；图写入附带 graph_id/node_id | 状态修改前后值 |
| `call` | call_kind(common/event) / target / depth / phase(enter/exit) | 调用边界 |
| `graph_node` | graph_id / node_id / node_type / phase / node_state / cause | 图节点进入/退出/阶段 |
| `graph_branch` | graph_id / node_id / port / to_node / active | 实际走通的图连线 |
| `graph_merge` | graph_id / node_id / mode(and/or) / count / required / fired / branch | AND/OR 汇合计数与结果 |

事件/页面/指令/条件/状态/图节点共享同一 `trace_id`（图条件除事件外为 0），
因此可以从事件记录定位到图节点，也可以从图节点看到它触发的事件。

## 3. 接入点（真实执行位置）

| 位置 | 接入内容 |
| --- | --- |
| `EventRunner.start` | 页面选择结果（`diagnose`）、拒绝事件、来源（图/交互组件） |
| `EventRunner._drive` | event_start / event_end、进入/退出上下文、取消/失败原因 |
| `EventRunner._execute_list` | command_start/end、WAIT 时长、ENTER_BLOCK/CALL/HALT/ABORT 结果 |
| `EventRunner._execute_call` | common / event 调用 enter/exit |
| `EventRunner._run_nested_event` | 子事件 trace_id、parent_trace_id、独立页面与结束记录 |
| `CmdIf` | 条件实际值、比较结果、then/else 分支 |
| `StateStore.set_value` | 新增 `write_observer`，在批处理之前回调旧值/新值；不改变事务语义 |
| `GraphRunner._activate/_propagate` | 节点进入/退出、实际连线 |
| `GraphRunner._activate_condition_once` | 条件实际值与 true/false 分支 |
| `GraphRunner._activate_merge_and/merge_or` | count/required/fired 与 OR 分支 |
| `GraphRunner._activate_event` | 设置待取来源，事件记录带 graph_id/node_id |
| `LevelGraphRunner2D`/`StudioRuntime.register_graph` | 把 RuntimeTrace 注入图执行器 |
| `StudioDebuggerPlugin` | 新增 `trace_node` / `trace_event` 消息，复用现有关卡图高亮通道 |
| `StateDebugPanel` | 同一 F2 面板新增「运行追踪」视图 |

**没有新增第二套关卡图调试器**：图高亮仍走 `StudioDebuggerPlugin`，F2 只是读取同一条 trace。

## 4. F2 面板

- 顶部：启用/关闭记录、事件 ID/名称过滤、状态标识过滤、结果过滤、清空、导出 JSON。
- 时间线（普通视图）：自然语言摘要——剧情开始/结束、事件页选择、开始执行指令、
  条件检查（显示名 + 实际值 + 进入分支）、游戏状态变化（显示名 + 前后值）、
  关卡图分支与汇合；显示/总条数、容量、丢弃数。
- 详情分层：自然语言详情 / 原始 JSON（专业模式），共享同一份数据。
- 双击：事件记录发送 `trace_event`（编辑器打开事件）；图记录/图条件发送 `trace_node`
  （编辑器定位对应图节点，图未打开时按 graph_path 自动加载）。游戏独立运行时消息无副作用。
- 导出：`user://rpg_event_studio_trace.json`。

## 5. 性能与安全

- 环形缓冲 `capacity` 默认 2000；超过后丢弃最旧记录并计数。
- `enabled` 默认 `OS.is_debug_build()`；`RPG_EVENT_STUDIO_TRACE=0/1` 可覆盖，
  `RPG_EVENT_STUDIO_TRACE_CAPACITY` 可调容量。正式导出版默认关闭。
- 所有记录方法只做字典/数组操作；关闭后立即返回。追踪异常不会改变事件控制流。
- 不记录原始输入按键/鼠标事件；只记录触发方式与来源节点路径。
- 不修改 `.tres` / `.tscn` / 存档结构。

## 6. 忠实性边界（不伪造）

- 页面选择记录由 `diagnose` 在事件开始时按当前状态重新求值；条件比较无副作用。
- 图条件记录 `trace_id=0`（不属于事件），但带 graph_id/node_id。
- 当前没有「调用另一个 EventDefinition」的已注册指令：`_run_nested_event` 路径存在且已接入追踪，
  但 UI 只能产生「公共事件」调用（同一事件内联执行，记录 call enter/exit）。
- 等待超时只是 `_pump` 的结束条件，运行时没有「timeout」事件结果；追踪不编造该状态。
- 并发图写入与事件重叠时，state 记录同时带事件 trace_id/command 与 graph_id/node_id，不强行归因。
