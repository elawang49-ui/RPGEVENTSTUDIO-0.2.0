# 16 · 场景对象引用规则与选择器

> 本轮解决「演出指令要手写节点路径」。规则先定，再实现；选择器与运行时共用同一套解析。

---

## 1. 引用是什么

一个「场景对象引用」由两个值组成，保存在指令参数里：

| 参数 | 含义 |
| --- | --- |
| `actor` / `target` | **相对场景根节点**的路径，例如 `Librarian`、`Group/NPC` |
| `actor_scene` / `target_scene` | 这个对象所属的**场景文件**，例如 `res://…/school_demo.tscn` |

两条一起看，才能确定「运行时到底该找谁」。

## 2. 解析规则（运行时）

`EventContext.resolve_scene_object(scene_path, path)`：

1. `path` 为空 → 视为未设置，指令跳过并写日志。
2. 取**当前场景**：`get_tree().current_scene`；取不到时退回 `root`（仅编辑器/测试环境）。
3. `scene_path` 非空且与当前场景的 `scene_file_path` **不一致** → 返回
   `wrong_scene:<当前场景>`，指令跳过并明确报错。
   **绝不按名字模糊匹配**，避免「显示的是 A，运行时动了 B」。
4. 在当前场景根下按路径精确查找；找不到 → `not_found:<path>`，指令跳过并报错。
5. `scene_path` 为空（旧数据）→ 只按当前场景解析，行为与上一轮一致，保证兼容。

## 3. 为什么不是「全局唯一 ID」

- 节点在 Godot 里没有稳定 ID；场景实例化后同一节点会存在多份。
- 用「场景文件 + 相对路径」是 Godot 自身的寻址方式，重命名/移动后必然失效，
  但失效是**可检测**的（找不到 → 报错），不会静默指到别的对象。
- 需要跨场景复用的事件：把 `scene_path` 留空（跟随当前场景），并保证两个场景里
  节点路径一致（例如都叫 `Librarian`）；这是可复用写法的约定。
- 更进一步的「逻辑角色 ID」（例如按 group 找）不在本轮范围，避免重建对象系统。

## 4. 编辑器行为

- 参数面板里目标显示为**名字**（鼠标悬停看完整路径），右侧有「选择对象…」与「清除」。
- 选择器列出**当前编辑场景**的节点树，两列：节点名 / 路径；同名节点靠路径区分，带搜索框。
- 确认后同时写入 `path` 与 `scene_path`；重新打开事件时按路径回显并自动选中。
- 失效提示（红字，不阻止编辑但要让你看见）：
  - 当前场景里找不到该节点 → 「⚠ 已失效：当前场景里找不到这个节点」
  - 引用的场景与当前编辑场景不同 → 「⚠ 这个对象属于另一个场景（复用事件时请重新选择）」
- 清除：两个参数一起清空。

## 5. 覆盖范围

| 指令 | 参数 |
| --- | --- |
| 移动角色 | `actor` + `actor_scene` |
| 镜头聚焦 | `target` + `target_scene`（留空 = 玩家） |

其他参数（偏移、时长、等待、淡入淡出方向、音量）不需要对象选择器，保持原有控件。
时长加了最小值 0.05 秒，避免 0 时长 tween 的边界问题。

## 6. 已知限制

1. 节点改名/移动后引用会失效，需要重新选择（有提示，不会静默错对象）。
2. 选择器只列**当前打开的场景**；预制体内部节点需要打开对应场景后再选。
3. 不支持按 group / 逻辑角色名解析（下一轮可加「按分组查找」作为可选模式）。
4. 跨场景复用事件时，要么保持节点路径一致（`scene_path` 留空），要么每个场景各配一份事件。
