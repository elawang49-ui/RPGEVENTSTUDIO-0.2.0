# 02 · 系统模块与数据架构

> 对应需求文档 §19 第 3 项、§12 数据架构。

---

## 1. 分层

```
┌──────────────────────────────────────────────────────────────┐
│ L4 界面层   editor/*（编辑器 UI）   runtime/ui/*（对话框）      │
├──────────────────────────────────────────────────────────────┤
│ L3 宿主层   EditorPlugin（编辑器）  Autoload RPGEventStudio（游戏）│
├──────────────────────────────────────────────────────────────┤
│ L2 执行层   EventRunner · GraphRunner · CommandHandler 集合     │
├──────────────────────────────────────────────────────────────┤
│ L1 服务层   StateStore · EventBus · ReferenceResolver ·         │
│             ConditionEvaluator · CommandRegistry · SaveService  │
├──────────────────────────────────────────────────────────────┤
│ L0 数据层   Resource 模型（无逻辑）：EventDefinition / EventPage /│
│             EventCommand / CommonEvent / LevelGraph /           │
│             LevelNode / StateDefinition / EventRef / NodeRef    │
└──────────────────────────────────────────────────────────────┘
```

依赖方向**只能向下**：

- `core/` 不许 `import`（preload）任何 `editor/` 下的类；由 `tests/` 中的静态检查脚本强制。
- `core/runtime/` 不许出现 `GraphEdit`、`EditorInterface`、`UndoRedo`。
- 指令 handler 不许直接操作 UI（对话框通过 `EventContext.presenter` 抽象接口调用，编辑器与游戏各给一个实现）。
- 只有一个方向的例外：`editor/` 可以读 `core/` 的一切。

## 3. 数据模型

### 3.1 类图（文字）

```
StateCatalog 1 ── * StateDefinition
EventDefinition 1 ── * EventPage 1 ── * EventCommand（树）
EventDefinition 1 ── 0..1 NodeRef（挂在哪个场景对象上）
CommonEvent 1 ── * EventCommand
LevelGraph 1 ── * LevelNode, 1 ── * LevelConnection, 1 ── * GraphGroup
LevelGraph 1 ── 1 LevelRef（属于哪个关卡）
LevelGraph * ── 0..1 EventRef / CommonEventRef / StateKey（节点参数里的引用）
```

### 3.2 字段设计

**EventDefinition（Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `event_id` | `StringName` | 场景内唯一，如 `librarian`；复制节点时校验冲突 |
| `display_name` | `String` | 编辑器显示名，参与搜索 |
| `pages` | `Array[EventPage]` | 顺序即优先级，**最后一个满足条件者生效** |
| `tags` | `PackedStringArray` | 用于筛选与图节点快速定位 |
| `schema_version` | `int` | 数据版本，迁移器用 |
| `notes` | `String` | 策划备注，不参与运行 |
| `bound_node` | `NodeRef` | 该事件挂载的场景对象（可为空 = 逻辑事件） |

**EventPage（Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `conditions` | `Array[ConditionClause]` | 全部 AND；子句内可嵌套 OR/NOT |
| `trigger` | `TriggerSpec`（Dictionary） | `type` + 参数，见 §3.3 |
| `commands` | `Array[EventCommand]` | 指令树根 |
| `repeat_policy` | enum | `ONCE` / `EVERY_TIME` / `ON_STATE_CHANGE` |
| `priority` | `int` | 同帧多事件排序，小的先 |
| `interruptible` | `bool` | 是否可被高优先级事件中断 |
| `through` | `bool` | 是否可穿过（接触触发用） |
| `appearance` | `Dictionary` | 外观覆盖：贴图/动画/朝向（空 = 用节点自身） |
| `self_switch_reset` | `bool` | 离开地图是否重置独立开关 |

**EventCommand（Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `cmd_uid` | `String` | 指令实例 id，撤销/复制/折叠用，不参与运行语义 |
| `type` | `StringName` | 对应 `CommandRegistry` 注册 id，如 `&"show_text"` |
| `params` | `Dictionary` | 由 `CommandSpec.param_schema` 约束 |
| `children` | `Array[EventCommand]` | then 分支 / 循环体 |
| `else_children` | `Array[EventCommand]` | else 分支 |
| `enabled` | `bool` | 条件编译开关，便于调试 |
| `comment` | `String` | 行内注释 |

> **为什么嵌套用数组而不是靠缩进**：RPG Maker 用缩进表达嵌套，导致复制/粘贴/撤销要重算深度。用显式 `children`/`else_children` 后，缩进只是渲染结果，数据结构永远合法。折叠与拖拽的重排规则见 `docs/08`。

**CommonEvent（Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `common_id` | `StringName` | 全局唯一 |
| `params` | `Array[ParamSpec]` | 名称/类型/默认值/是否必填 |
| `commands` | `Array[EventCommand]` | 指令树 |
| `max_recursion` | `int` | 默认 8，超过报错并中止 |

**LevelGraph（Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `graph_id` | `StringName` | 关卡内唯一 |
| `level_id` | `StringName` | 关联关卡，如 `school` |
| `nodes` | `Array[LevelNode]` | 见 `docs/05` |
| `connections` | `Array[LevelConnection]` | `from_node/from_port/to_node/to_port` |
| `groups` | `Array[GraphGroup]` | 分组框（标题/颜色/成员 id） |
| `stages` | `Array[StageDefinition]` | 阶段定义与转移 |
| `entry_node` | `StringName` | 起点 |
| `schema_version` | `int` | 迁移用 |
| `view_state` | `Dictionary` | 缩放/滚动位置（**属于编辑态，不参与运行**） |

**StateDefinition（Resource）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `String` | 点分命名，如 `School.Stage`，作用域由前缀或字段决定 |
| `scope` | enum | `GLOBAL` / `LEVEL` / `LOCAL` |
| `type` | enum | `BOOL` / `INT` / `FLOAT` / `STRING` / `ENUM` |
| `default` | `Variant` | 缺省值 |
| `enum_values` | `PackedStringArray` | `type == ENUM` 时有效 |
| `category` | `String` | 编辑器分组，如 `剧情/学校` |
| `description` | `String` | 悬停说明 |
| `persistent` | `bool` | 是否进存档（调试用临时状态可关） |

## 4. 存储方案评估（需求 §12）

| 方案 | 优点 | 缺点 | 适用 |
| --- | --- | --- | --- |
| 纯 Resource `.tres` | 类型安全、编辑器原生检视、`uid://` 引用、可继承 | 参数常用 `Dictionary`，检视器必须自写；文本 diff 较吵 | **主方案** |
| 纯 JSON | diff 干净、AI 友好、跨工具 | 无类型、无 UID、Godot 检视器不支持、易被手改坏 | 导入/导出、AI 交换 |
| 混合（推荐） | 结构用 Resource，参数用 Dictionary；JSON 仅作交换格式 | 需要一套 schema 校验 | ✅ |

**决策：混合。**

- 事件、图、状态目录全部 `.tres`。
- 指令参数是 `Dictionary`（避免为 100 条指令写 100 个 Resource 子类）；参数合法性由 `CommandSpec.param_schema` 在**保存时 + 加载时 + 运行时入口**三处校验。
- `tools/` 提供 `export_json` / `import_json`，用于 AI 生成、代码评审与回归测试夹具。
- 版本化：`schema_version` 单调递增，`core/model/migrations/` 里一个版本一个迁移函数，加载时链式升级并写回。

**文件布局约定**

```
res://events/<level_id>/<event_id>.tres         局部事件
res://common_events/<common_id>.tres            公共事件
res://levels/<level_id>/graph_<graph_id>.tres    关卡总控图
res://state/state_catalog.tres                   状态定义总表
```

## 5. 引用策略（关键）

三类引用，全部避开"裸字符串 + 裸路径"：

| 类型 | 形态 | 解析 | 失效处理 |
| --- | --- | --- | --- |
| `ResourceRef` | `{uid: "uid://xxx", path: "res://..."}` | 先 UID，再路径 | 两者都失败 → 标红，图节点变"失效节点"，仍保留数据 |
| `NodeRef` | `{scene_uid, path_from_owner, unique_name, cached_label, class_hint}` | 精确路径 → `%unique_name` → 同 owner 下按名字搜 → 按 class+分组搜 | 可一键"重新指定"，原数据保留 |
| `StateKey` | `"Global.Story.Chapter"` / `"School.Stage"` / `"@@self.SelfSwitchA"` | 前缀判作用域；`@@self` 在编译期替换为当前事件 id | 未定义 key → 校验器报"未使用/未定义"，运行期读默认值并记诊断 |

**为什么 NodeRef 要存 4 个字段**：场景可能被实例化（路径前缀变化）、节点可能被重命名（路径失效）、节点可能被替换（class 变化）。多字段是为了**尽量自动恢复，恢复不了也能人工指认**，而不是直接报错丢失数据。

## 6. 指令注册表（CommandRegistry）

指令不是 `match type:` 大 switch，而是注册表：

```
CommandSpec {
  id: StringName            # &"show_text"
  display_name: String      # "显示文字"
  category: StringName      # &"dialogue"（对话与剧情/流程控制/...）
  icon: Texture2D
  keywords: PackedStringArray  # 搜索用，含拼音首字母
  param_schema: Array[ParamSpec]
  handler: GDScript          # extends CommandHandler
  editor: GDScript           # 可选：专用参数编辑器，缺省用自动生成
  is_async: bool             # 是否可能挂起帧
  is_block: bool             # 是否带 children（条件/循环）
  validate: Callable         # 额外校验（引用是否存在、参数组合是否合法）
}
```

好处：

1. 新增指令 = 新增 1 个 handler + 1 行注册，**不动任何 if/else**。
2. 编辑器参数面板由 schema 自动生成，新指令零 UI 代码。
3. AI 生成的事件数据可以按 schema 校验后再导入（需求 §15）。
4. 校验器、搜索、分类、快捷键全部由注册表驱动。

## 7. 校验器（加载时 / 保存时 / 编辑器手动）

| 校验器 | 检查内容 | 输出 |
| --- | --- | --- |
| `SchemaValidator` | 指令 type 已注册；参数符合 schema；必填项存在 | 错误 / 警告 |
| `ReferenceValidator` | 事件、公共事件、图、场景节点、状态 key 是否存在 | 错误（标红可点击定位） |
| `GraphLinter` | 不可达节点、环路、悬空连接、缺入边、缺出边、重复触发 | 警告 |
| `StateUsageAnalyzer` | 未定义状态、只写不读、只读不写、默认值类型不符 | 警告 |
| `EventPageAnalyzer` | 条件永假（如 `Stage > 5` 而最大为 4）、无指令页、重复条件 | 提示 |

校验器**只报告不修改**；修复动作由用户显式触发，且走撤销栈。

## 8. 运行时装配（谁 new 谁）

```
Autoload RPGEventStudio (Node)
 ├─ StateStore            ← 从 StateCatalog 初始化默认值
 ├─ EventBus              ← 信号集线器
 ├─ Registry              ← CommandRegistry + 事件目录（扫描 res://events）
 ├─ EventRunner           ← 持执行队列、并行预算
 ├─ GraphRunner           ← 每关卡一个实例
 ├─ SaveService
 ├─ Presenter (Dialogue/Cinematic)
 └─ Adapters（Item/Quest/Enemy/Player 的默认空实现，可被项目替换）
```

编辑器侧**不 new 上面这套**，而是：

```
EventStudioPlugin
 ├─ EditorStateStore      ← 同 StateStore 类，独立实例
 ├─ EditorRegistry        ← 复用 CommandRegistry（只读）
 ├─ PreviewRunner         ← 同 EventRunner，但 Context 是 Mock
 └─ DocumentManager       ← 打开的事件/图文档、脏标记、撤销上下文
```

这样"编辑器里试跑"和"游戏里真跑"走同一条代码路径，但互不污染。
