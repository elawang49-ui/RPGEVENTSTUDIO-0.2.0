# 17 · 版本管理指南（Git）

> 基线提交：`chore: establish project baseline`。仓库根：`RPGEVENTSTUDIO/`。

## 1. 开始一轮工作前

```bash
cd RPGEVENTSTUDIO
git status                 # 有没有没提交的改动
git log --oneline -5       # 最近做了什么
bash tools/check_baseline.sh   # 一键：工作区干净 + 跑 i18n 检查（见下）
```

如果 `git status` 有你不认识的改动，先 `git diff` 看清楚，再决定是保留还是恢复。

## 2. 做完一个功能/修复后

```bash
git diff                   # 改了什么
git diff --stat            # 改了哪些文件、多少行
git status                 # 有没有临时文件混进来
```

重点看三类文件：`.tres` / `.tscn`（内容数据）、`ui.csv`（翻译）、脚本。确认没有 `.bak`、`.tmp`、`.godot/` 被加进来。

## 3. 什么时候提交

- 一个可验证的功能或修复完成、相关测试通过之后；
- 提交前至少跑：`tests/run.gd` + 受影响模块的测试；
- 改翻译要额外跑 `tools/check_i18n.gd`；
- 不要把「一半没跑通」的改动提交成基线。

```bash
git add -A
git commit -m "feat: 演出指令支持等待音效播放完成"
```

## 4. 查看最近提交

```bash
git log --oneline -10
git show HEAD --stat
git log -p -- docs/14-上手教程-从零做一段剧情.md   # 某文件的历史
```

## 5. 恢复误改的文件

```bash
git restore 路径/文件            # 丢弃未提交修改（不可恢复，先 git diff 确认）
git restore --staged 路径/文件   # 只取消暂存，保留工作区修改
git checkout HEAD~1 -- 路径       # 取回上一次提交的版本
```

## 6. 安全撤销错误提交

```bash
# 还没推送（本地仓库）：
git reset --soft HEAD~1    # 撤销提交，改动仍在暂存区
git reset HEAD~1           # 撤销提交，改动回到工作区

# 已经提交且想保留历史：
git revert <commit>        # 生成一个反向提交，最安全
```

**不要**在没确认前用 `git reset --hard`：它会丢掉未提交的改动。

## 7. Git 与 SafeFile 的分工

| | Git | SafeFile / SafeCsv |
| --- | --- | --- |
| 管什么 | 整个工程的历史状态 | 单次文件写入 |
| 能恢复什么 | 任意已提交版本 | 本次写入前的原文件（`.bak`） |
| 什么时候生效 | 你手动提交 | 脚本写入时自动 |
| 防什么 | 改错、删错、想回到昨天 | 脚本异常导致文件被写坏 |

两者不能互相替代：Git 防不住「还没提交就被脚本写坏」，SafeFile 也防不住「提交了但内容本身就错」。所以批量写入走 `SafeFile`，每天收工前提交一次 Git。

## 8. 远程与备份
