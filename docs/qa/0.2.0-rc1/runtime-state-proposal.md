# 事件状态事务方案（用户已确认，实施与验证中）

基线 9368e33。StateStore 的现有 transaction/commit 是立即写值、延后通知的批处理；宿主 School 的存档桥使用 snapshot/restore，格式必须保持不变。GamePrototype 有自己的插件修改，不能直接覆盖升级。

## 兼容部分

- 保留 StateStore 所有现有方法、信号、快照格式及宿主直接 set_value 的立即可见性。
- transaction/commit 使用嵌套深度；最外层 commit 才发批量通知。先从 pending 字典摘下本批通知，再广播，避免监听器重入破坏下一批。
- once 仅在成功完成后消耗；运行中由已有 event_id 闸门阻止重入。取消/失败允许重试。

## 需要用户确认的事件语义调整

建议事件执行使用内部 StateStore 会话视图（仍满足 StateStore 类型），以解决“跨 await 长事务”无法安全回滚的问题：

1. 顶层实例从共享状态读取；本实例写入仅进入会话覆盖层。读取能看到自身未提交写入。
2. 同步嵌套事件和公共事件加入父会话，父取消会级联取消子事件并丢弃整个会话。
3. COMPLETED 时校验读写冲突，再用共享 StateStore 批处理一次提交；CANCELLED/FAILED 丢弃覆盖层，不发正式状态通知、不消耗 once。
4. 若事件读取/写入的键在执行期间被宿主或另一个事件修改，事件以 FAILED 和明确 conflict 原因结束，不覆盖更新、不自动重放有外部副作用的指令。
5. 宿主直接调用 StateStore 的通知、snapshot/restore 保持现状；存档只捕获已经提交的状态，不保存执行中会话。
6. 自定义 handler 继续使用 ctx.get_state/set_state 或 ctx.state 的既有方法；ctx.state 对象身份将变成会话视图。直接持有全局 runtime.state 写入会绕过会话，属于显式宿主写入，不能被事件回滚。
7. 回滚范围只包括插件状态。道具/任务/场景/动画等宿主外部副作用继续由适配器和 on_cancel 负责，不承诺分布式事务。

这改变事件执行期间的可见性以及 ctx.state 的对象身份，属于公共行为契约调整。用户于 2026-11-02 已确认“事件完整成功才写入开关；中途取消不留下半成品”，可以实施；不增加 Resource/存档字段，不重做事件资源模型。

## 验证要求

并发独立写、同键冲突、宿主写入、嵌套成功/失败/取消、开始信号内取消、等待后取消、once 重试、存档桥、旧自定义 handler、Graph 只见完整提交。严禁用整库 snapshot 恢复取消状态。
