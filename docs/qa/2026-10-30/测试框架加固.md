# 测试框架加固 · 2026-10-30

## 背景

`feat/unified-input` 的 `_test_input_registry()` 因 `Dictionary` / `Array` 类型错误中断，
后续 11 项用例没有执行，但 `tests/run.gd` 仍打印“失败 0”。原因是：

- GDScript 的运行时错误只中止当前函数，调用方继续执行；
- `_report()` 只统计已经执行的断言，不统计“本应执行但没执行”的用例；
- 进程退出码只取决于 `_failures`，不取决于运行时错误。

## 机制

1. `tests/run.gd` 每个测试函数由 `_case_begin` / `_case_end` 包裹；
   `_case_verify` 在函数返回后检查完成标记，缺失即 `CASE_INCOMPLETE` + 失败。
2. 每个测试函数末尾必须有 `_case_end()`；提前 `return` 的分支也要先标记。
3. `RESULT: PASS/FAIL` 与 `CASES：预期/完成` 进入最终汇总。
4. `tools/test_runner.py` 外部校验：
   - 必须有最终汇总，否则 FAIL；
   - `SCRIPT ERROR`（区分 Parse Error / 运行时异常）默认 FAIL；
   - `ERROR:` 默认 FAIL；只有显式 `EXPECTED_ERROR_BEGIN/END` 区间或逐条列出的
     已知引擎退出诊断放行（GVL 的 UndoRedo/GraphFrame 诊断单独列在 gvl 下）；
   - 每个套件检查数与 `tools/test_counts.json` 对照；
   - 所有套件退出码必须为 0。
5. 预期负向测试：presenter 缺少协议方法的 `push_error` 用
   `_expect_error_begin/end` 显式包裹，运行器只放行该区间。
6. 故障注入：`RPGEVENTSTUDIO_TEST_FAULT=type|null|skip|expected_error`
   以及 `tests/faults/` 下的独立故障脚本。

## 故障注入结果

| 注入 | 预期 | 实际 |
| --- | --- | --- |
| run.gd 类型错误 | FAIL | FAIL（CASE_INCOMPLETE + 运行时异常） |
| run.gd 空引用 | FAIL | FAIL |
| run.gd 未完成函数（skip） | FAIL | FAIL（CASE_INCOMPLETE） |
| 预期负向错误 | PASS | PASS（区间放行） |
| 无最终汇总 | FAIL | FAIL |
| 启动即退出 | FAIL | FAIL |
| 脚本解析失败 | FAIL | FAIL（Parse Error） |
| 断言失败 | FAIL | FAIL（汇总 1 项失败） |
| 子函数中断但仍打印 PASS | FAIL | FAIL（运行时异常） |

## 说明

- 未引入 try/catch：GDScript 4.7.2 的运行时错误不可捕获；改用完成标记 + 外部进程校验。
- `tools/test_counts.json` 是测试数量快照；新增/删除用例时必须同步更新，否则运行器 FAIL。
- 直接 `godot --script` 仍然可用，但推荐用 `test_runner.py` 作为 CI/验收入口。
