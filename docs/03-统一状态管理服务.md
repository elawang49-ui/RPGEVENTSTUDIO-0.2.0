# 03 · 统一状态管理服务

> 文档状态：早期架构设计草案，不是当前公共 API 清单。0.2.0-rc1 的实际方法、同步 handler/WAIT 协议、事务可见性和存档格式以 [发布接入说明](release/INSTALL.md) 及源码为准；本文尚未实施的检查点/调度预算等内容不能作为已交付能力。
> 对应需求文档 §19 第 4 项、§6。

---

## 1. 定位

`StateStore` 是整个插件的**唯一真相源**之一（另一个是事件/图的数据资源）。它必须满足：

1. 三作用域（Global / Level / Local）统一 API，调用方不关心存储细节。
2. 强类型：写入类型不符**立即报错**，不做静默转换（避免"字符串 1"的经典事故）。
3. 变化通知可订阅、可批量、可去抖（总控图求值靠它）。
4. 全部状态可快照/恢复（存档、调试、编辑器预览回滚）。
5. 纯 `RefCounted`，不依赖 `SceneTree`，可在编辑器与游戏两侧各实例化一份。

---

## 2. 作用域

| 作用域 | 键形态 | 生命周期 | 存档 | 示例 |
| --- | --- | --- | --- | --- |
| Global | `Global.<Domain>.<Name>` | 跨地图、跨关卡 | ✅ | `Global.Story.Chapter = 3`、`Global.Player.HasSpecialKey = true` |
| Level | `<LevelId>.<Name...>` | 当前关卡，离开关卡按配置保留或重置 | ✅（按关卡分槽） | `School.Stage = Exploration`、`School.BasementUnlocked = false` |
| Local | `@@self.<Name>` 或 `<EventId>.<Name>` | 单个事件实例 | ✅（随事件状态） | `@@self.SelfSwitchA = true`、`ClassroomDoor.Opened = false` |

**设计取舍**

- 不用三套 API（`set_global`/`set_level`/`set_local`），只有一套 `set(key, value)`，作用域由 `StateDefinition.scope` + key 前缀决定。理由：指令参数里用户选的就是一个 key，不该再由指令作者决定 API。
- Level 作用域的 key **必须带关卡前缀**（`School.Stage`），因为将来的跨关卡剧情（如"学校完成后解锁医院"）需要读别的关卡状态；用 `@@level.Stage` 这种相对写法只在 `LevelGraph` 内部作为语法糖，保存时展开为绝对 key。
- Local 的 `@@self` 只在事件/公共事件内部有效，**不得种进公共事件**（公共事件被多处调用，Local 会冲突）——校验器直接报错。

## 3. 类型系统

| 类型 | 存储 | 比较 | 特殊 |
| --- | --- | --- | --- |
| BOOL | `bool` | `==` | 开关、`== true` 可简写 |
| INT | `int` | `== != > >= < <=` | 变量加减乘除、自增 |
| FLOAT | `float` | 同上 | 与 INT 比较时按数值比较，但**写回仍按定义类型** |
| STRING | `String` | `== !=`、`contains/startswith` | 任务名、状态标签 |
| ENUM | `StringName`（存名字） | `== !=`、按定义顺序 `> <` | 关卡阶段；`School.Stage = Chase` 而非 `= 3`，编辑器下拉选择 |

**强制规则**

- 写入未定义 key → 报错（可在项目设置里降为警告）。
- 读取未定义 key → 返回该类型的零值 + 记录一条 `undefined_read` 诊断（编辑器的"未使用状态检测"就靠这条）。
- `int` 写 `float` 字段：`is_equal_approx` 语义，但类型保持 FLOAT。
- `ENUM` 写入不存在的成员 → 报错并列出合法值。

## 4. 事务与通知

```
store.transaction()          # 开启批处理
  set A, set B, set C
store.commit()               # 一次性发通知，按 key 去重
```

- 批量期间只记录"脏 key 集合 + 首末值"，提交时按 key 排序发 `state_changed(key, old, new)`。
- 总控图求值监听的是**批量提交后的通知**，不是每次 set。否则一个 Action 节点改 5 个状态会触发 5 轮图求值。
- 去抖：同一帧内多次 commit 合并为一次（`state_batch_committed(keys)`）。
- 图求值有预算（默认 2ms/帧），超预算的求值排队到下一帧，并标记"图求值滞后"（调试面板可见）。

## 5. 关卡阶段（Stage）

阶段不是特殊系统，而是 **Level 作用域的一个 ENUM 状态** + 一张转移表：

```
StageDefinition {
  id: StringName            # &"exploration"
  label: String             # "探索"
  order: int                # 0..N，用于比较
  on_enter: Array[EventCommand]   # 可选：进入时执行
  on_exit: Array[EventCommand]
  graph_node: StringName    # 对应总控图上的 Stage 节点 id
}
```

- 运行时只有一条规则：`set("<LevelId>.Stage", new_stage)`，**阶段切换的唯一入口**。
- 状态变化 → `StageWatcher` 监听 → 触发 `on_exit`（旧）/`on_enter`（新）→ 通知总控图高亮。
- 图上的 Stage 节点只是"阶段状态的镜像 + 可视化"，不持有自己的阶段变量。
- 好处：存档只需存一个 ENUM；不会出现"图说在追逐、状态说在逃生"的分裂。
- 进入条件（前置依赖）写在图里（Condition → Stage 节点），不在阶段定义里，避免两套条件系统。

## 6. 引用查询（编辑器用，非运行时）

需求 §5.5 要"点一个状态就能看到谁读谁写"。做法是**静态索引**，不是运行时埋点：

```
DependencyIndexer.build(events, common_events, graphs)
  -> writes: { key -> Array[SourceRef] }   # set_state / 变量运算 / 图 Action 节点 / 阶段切换
  -> reads:  { key -> Array[SourceRef] }   # 条件分歧 / 图 Condition 节点 / 阶段进入条件
  -> calls:  { event_ref -> Array[SourceRef] }
  -> depended_on: { graph_node -> Array[条件节点] }
```

- 编辑器打开工程时增量构建（按文件 mtime），状态监视面板用 `writes[key]` / `reads[key]` 呈现。
- 点击条目跳转：事件 → 打开事件编辑器并选中指令；图 → 打开总控图并居中节点；场景 → 在 2D 视口选中节点。
- "影响分析" = 从 `writes[key]` 出边做 BFS（读该 key 的条件/节点 → 其下游 → ...），限制深度 4，避免爆表。

## 7. 调试能力（需求 §6.3）

| 能力 | 实现 |
| --- | --- |
| 运行时查看 | 状态监视 dock：按作用域/分类折叠；变化行闪一下高亮 |
| 运行时修改 | 允许手改，标记 `debug_override`；"重置为存档值"一键回退；调试修改**不写入存档**（除非显式勾选） |
| 条件不满足原因 | `WhyNotTriggered` 求值器：给定事件 id，返回每条 condition 的 `[✓/✗] + 实际值 vs 期望值 + 该状态的来源` |
| 变化历史 | 环形缓冲最近 500 条 `state_changed`，带 tick 与触发来源（事件 id / 图节点 id） |

`WhyNotTriggered` 输出直接对应需求 §14 的示例：

```
事件：地下室剧情   状态：未触发
  ✓ 已获得教师日志        Global.Story.DiaryFound = true
  ✗ 尚未调查教室          School.ClassroomClueFound = false（最后写于 事件 classroom_desk/c3）
  ✓ 地下室已解锁          School.BasementUnlocked = true
```

## 8. 存档快照（状态部分）

```
StateStore.snapshot() -> Dictionary:
{
  "version": 1,
  "global": { "Story.Chapter": 3, "Player.HasSpecialKey": true },
  "levels": { "school": { "Stage": "chase", "BasementUnlocked": true } },
  "local":  { "classroom_door": { "SelfSwitchA": true } }
}
```

- 只存 `persistent == true` 且有别于默认值的项（体积优化），恢复时先铺默认值再覆盖。
- 快照里**不含**运行时对象引用，纯值。
- 版本迁移在 `core/save/migrations/`，与数据 schema 迁移分开（存档版本独立于资源版本）。

## 9. API 草案（只示意签名，不是实现）

```
class StateStore:
    func setup(catalog: StateCatalog) -> void
    func get(key: String, fallback: Variant = null) -> Variant
    func set(key: String, value: Variant) -> Error
    func has(key: String) -> bool
    func get_type(key: String) -> int
    func add(key: String, delta: Variant) -> Error          # int/float
    func compare(key: String, op: int, value: Variant) -> bool
    func transaction() -> void
    func commit() -> void
    func subscribe(keys: PackedStringArray, cb: Callable) -> int
    func unsubscribe(handle: int) -> void
    func snapshot() -> Dictionary
    func restore(data: Dictionary) -> Error
    func reset(scope: int) -> void
```

内部存储：`Dictionary[String, Variant]` 三张表；`StringName` 做 key 驻留；订阅表 `key -> Array[Callable]`，批量提交时对脏 key 逐个派发。

## 10. 反模式（代码评审红线）

1. ❌ 指令 handler 里直接 `ProjectSettings` 存状态 → 必须走 `StateStore`。
2. ❌ 图节点自己缓存状态值 → 每次求值都从 `StateStore` 读。
3. ❌ 用 `Node` 的 `_process` 轮询状态变化 → 用订阅。
4. ❌ 编辑器实例与运行时实例共享同一个 `Dictionary` → 只共享 `StateCatalog`（只读定义）。
5. ❌ 状态 key 用数字编号（`var_001`）→ 必须可读命名；只允许导入旧数据时映射。
